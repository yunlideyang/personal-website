- 前端严格按后端文档对接：列表用 `GET /api/blog/juejin/posts`，详情用 `GET /api/blog/juejin/posts/:articleId`。
- 修复博客详情页“显示的是标签”（正文被当成纯文本展示）的渲染问题。
- 不再生成任何“后端文档”类新文档，只改前端代码。

## 问题假设（与“显示标签”高度吻合）
- 后端返回的 `content` 实际是 HTML 字符串，但 `contentType` 不是严格的 `'html'`（可能为空/大小写不同/值为 `'markdown'`/`'text'`），导致前端走 `<pre>` 分支，于是你看到 `<p>...` 这类标签文本。
- 或后端返回结构有一层包装（例如 `{ data: {...} }`），导致 `content/contentType` 取不到或取错。

## 修改方案
### 1) 先用真实接口回包“对齐字段”
- 在本地/测试环境请求：
  - `/api/blog/juejin/posts?cursor=0&limit=5`
  - `/api/blog/juejin/posts/:articleId`（从列表 url 解析得到）
- 记录实际 JSON 的字段名、`contentType` 取值、以及 `content` 是否为 HTML/Markdown。

### 2) 增加“响应归一化”以兼容轻微差异
- 在 `api/juejinBlogApi.ts`（或新增一个 `normalize` 工具）做容错：
  - 兼容 `{ data: ... }`、`{ result: ... }` 这类一层包装（如果存在）。
  - `contentType` 做 `toLowerCase()`，接受 `'html' | 'markdown' | 'text'` 及大小写变体。
  - 加一个启发式判断：当 `contentType` 缺失/不可信，但 `content` 看起来像 HTML（例如 trim 后以 `<` 开头且包含闭合标签），则按 HTML 渲染。

### 3) 修复详情页渲染策略
- 详情页组件继续放在 `src/components/BlogPostDetail`（已符合你的要求）。
- 具体渲染：
  - HTML：继续用 `dangerouslySetInnerHTML`，但把当前正则版 sanitize 替换为基于 `DOMParser` 的“删除危险节点/事件属性/JS 协议”的实现，避免误删正常内容且更稳。
  - Markdown：两种可选路径（我会默认走更稳的 A，再给你 B 作为增强）：
    - A（不新增依赖）：仍用 `<pre>` 展示 Markdown，但保证 HTML 字符串不会误走此分支。
    - B（增强阅读体验，需新增依赖）：引入 `react-markdown + remark-gfm + rehype-sanitize`，安全渲染 markdown（禁用危险 HTML）。

### 4) 小修补（不改变功能）
- 列表渲染的 `key` 从 `title` 改为 `url`，避免重复标题导致 React 复用异常。
